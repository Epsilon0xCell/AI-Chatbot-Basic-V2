AI Chatbot Basic V2: knock first

Jordan lives here. State your name exactly, or you stay outside.

I wrote a small chatbot named Jordan with ChatterBot. Jordan uses the BestMatch logic adapter and SQL storage, and I left read_only set to False, so Jordan learns from the chats it has. Training and chat history live in a local SQLite file created in the folder you run the program from. Before any chat starts, Jordan asks for your identity and checks it exactly. That check is the whole front of this page, because it is the whole front of the program.

The doorstep: the identity check

When I run main-v2.py, the program builds Jordan, trains the English corpus, and then prints State your identity please:. What I type next is compared exactly as typed, case included. Mark gets in. Jane gets in and is told Mark is out. Anyone else is denied and the program ends before any custom training or chat.

The check itself, copied from the file

From main-v2.py, lines 51 to 67 at head 3679e1a019479f1f87a4ee057acfb0f061c330e7. I show it exactly, nothing clipped.

    identity = read_identity()
    if identity is None:
        return 0

    # Same exact match rule as main.py: "Mark" and "Jane" as typed,
    # case included. Anything else, including "mark", is denied below.
    if identity == "Mark":
        print("Welcome, Mark. Happy to have you at home.")

    elif identity == "Jane":
        print("Mark is out right now, but you are welcome to the house.")

    else:
        print("Your access is denied here.")
        # Returning here is what makes the denial real. Without it the
        # training below would still run for a denied identity.
        return 0

The hallway: corpus training

Once Jordan is built and before the identity question, I train the full English corpus with train_all_data. That training runs on every start, so startup takes a while. I accept that rather than tracking what was already trained, and the trained data goes into the same local SQLite file as the chat history.

One point I want plain, because this page used to get it wrong: the repo has a training-data/ folder of English corpus YAML files, and no code in the repo reads that folder. train_all_data trains chatterbot.corpus.english from the installed chatterbot-corpus package. The folder is a local reference copy whose files match the package files. Editing a YAML file in that folder changes nothing Jordan learns.

Setup, from my README: I verified this on Python 3.12 with ChatterBot 1.2.11. Install with pip install -r requirements.txt, then run python -m spacy download en_core_web_sm as a separate step. Without that model, creating the bot fails.

The rooms: the custom answers

After the door, I train the custom storyline answers. One answer is shared: asked who owns the house, Jordan answers that Mark Nicholas is the owner of this house. I train that pair for every accepted identity, Mark and Jane both.

Mark's personal answers are trained only when the identity is Mark: where he was born (Seattle), his favourite book (The Great Gatsby), his favourite movie (Interstellar), and his favourite sport (baseball). Jane gets the house pair and the general corpus, and nothing personal. In main-v2.py I train each personal pair as its own list, in its own call, so no answer is learned as the reply to the previous answer.

The way out: the bye words

The chat loop starts with Jordan saying hello and asking how it can help. I leave by typing one of four bye words: bye, bye jordan, good bye, or goodbye. Case and surrounding spaces are ignored for those words, which is the opposite rule from the identity check at the door, and that contrast is deliberate in my code: the gate is a name, the exit is a courtesy.

An empty line is asked again instead of being sent to the bot. Closing the input or pressing Ctrl-C ends the chat cleanly too, with the same goodbye: Jordan: Good bye and have a blessed day!

I have 13 tests in test_chatbot.py covering the bye word rule, the chat loop driven by a stand-in bot, the identity prompt closing cleanly on EOF, and both entry points run as subprocesses. The live chat loop itself is untested, because it needs ChatterBot installed and my tests run on machines without it by design. I would rather say that here than let the test count imply more than it covers.

Honest notes

  • Corpus training runs on every start, so startup takes a while. I did not add a trained once flag.
  • Because read_only is False, Jordan learns from chats, and the SQLite file grows. Nothing in this repo prunes it.
  • Run the program from a different folder and you get a second, separate database there, with none of the earlier chats in it.
  • BestMatch is the only logic adapter I use. A question with no close match still gets whatever BestMatch rates highest, even when that match is weak.
  • The training-data folder is a reference copy only. See the hallway section above for the full point.
  • The live chat is the one part my 13 tests do not cover, for the reason given in the way out section.
